# 请求审计值明细是 usage-owned、加密、默认关闭的短期旁路

既有约束（ADR 0001／0002）把 usage-owned 请求审计限定为协议元数据与事件骨架：不保存模型正文，不保存认证凭据原文，也不保存任何头**值**。这个约束对「复核某次 Claude Code 调用到底发了什么头、带的是哪个设备／会话／账号」是不够的：头名、体量与存在性无法回答这类问题。

本决策**不修改** ADR 0001 与 ADR 0002，也不放宽 request_audits 的任何列。它另开一条有范围、默认关闭、短期、权限隔离的旁路。

## 决定

新增 `request_audit_value_details` 表（迁移 253），与 `usage_logs` 一对一：

- **usage-owned**：`usage_log_id` 唯一且外键级联；没有任何独立保留期，使用记录被删除时整行消失。
- **只在审计行已存在后写入**：写入是同一条 SQL 里的 `INSERT ... SELECT ... WHERE EXISTS (SELECT 1 FROM request_audits WHERE usage_log_id = $1)`。没有审计行的调用不写值明细，因此「先有 request_audits、再有值明细」是存储层不变量，而不是调用方的约定。
- **范围极窄**：只对入站路由 `/v1/messages` **且**这次逻辑请求真的以 Anthropic 协议形态发出时采集。`/v1/messages` 被改写到别的上游协议记 `skipped_out_of_scope`；其它路由不落行（未采集）。
- **只保存值**：入站请求头值、每次真实上游尝试的请求／响应头值、`metadata.user_id` 解析出的 `device_id`／`session_id`／`account_uuid`、最终模型与每次尝试的模型、尝试耗时与代理内部 ID。**不保存**模型正文、Cookie／Set-Cookie／Authorization／X-Api-Key／Proxy-Authorization／WWW-Authenticate 等凭据类头的值、未知头名、原始 `http.Header`。
- **头值是有界的值列表**：单值头是单元素列表，多值头原样保留（最多 4 个）。不取第一行、不静默截断；确有条目没被收下时载荷带 `truncated`，使「客户端只发了这些」与「我们只收了这些」可区分。
- **明文信封不含模型名**：模型别名由调用方任意指定（既有审计因此从不落库模型名，见 `SanitizeRequestAuditAttempt`），所以模型名只进密文。明文列只有路由、协议、客户端状态码与时间——都是闭集枚举或有界的服务端事实。
- **每个用途一把密钥**：载荷用 AES-256-GCM 加密，密钥由配置的 TOTP 主密钥经 HKDF-SHA256 以独立 info 标签派生（`sub2api:request-audit-value-detail:v1`），与错误诊断正文／头值均不共用。主密钥缺失、格式不对或**不是手动配置**（随机生成的进程级密钥）时加密器为 `nil`，此时值一律不留存，**没有任何明文回退**。
- **7 天披露**：`expires_at = created_at + 7 天`。API 在到期时刻**精确地**立即拒绝揭示（按创建时间即时计算，不受清理进度影响）。在线主库上的密文由周期批处理物理清除（默认约每 10 分钟一轮、每轮至多 500 行）；停机、积压或单轮未取完都会推迟它，**没有硬性最大延迟**，也不承诺任何延迟数值。清理只置空密文列并记 `purged`，保留整行信封，使「曾留存、现已清除」与「从未留存」可区分。副本、备份与 PITR 中的旧数据是已声明的剩余风险；本功能不是合规删除或数据主体擦除手段。
- **默认关闭且需书面风险确认**：门控键 `request_audit_value_detail_settings` 默认关闭；只有存量布尔值为真**且**存在一条覆盖当前语句版本、逐字匹配的书面确认记录（`request_audit_value_detail_risk_acknowledgement`）时才允许采集；开启那一刻还要求密钥可用。直接改库或其它管理入口把布尔值写成真都不足以打开采集。
- **值快照默认不被复制**：传输层只在请求上下文带 `httpattempt.WithClaudeHeaderValueCapture` 标记时才构建头值与 `metadata.user_id` 的值快照。关闭态下热路径上不会读取、也不会复制任何明文值——不是「采了再丢」，而是根本不构造。
- **默认视图不含值**：`GET /admin/usage/:id/request-audit/value-detail` 返回的信封类型里没有值字段（类型保证）；真实值必须由管理员**显式** `POST` 同一路径揭示，响应禁止中间缓存（`Cache-Control: no-store, private`）。
- **失败不影响主流程**：写入 fail-open，任何失败只写一条不含值的日志；读取区分「没有行」「从未留存」「已到期／已清除」「存储不可用」四种结论，不把故障显示成「值已消失」，也不把「已到期」显示成「从未采集」。

## Considered Options

- 把值直接加进 `request_audits` 的列
- 复用 429 错误诊断（ADR 0005）的记录与开关存放头值
- 另建 usage-owned、独立开关、独立密钥、独立到期时刻的旁路

选第三项。第一项会让长期存活的审计行永久带上调用方可控的值（模型别名、设备与会话标识），即使到期后也无法回收，直接违反 ADR 0001；第二项会把「上游 429 的响应事实」与「客户端的请求事实」耦合到一张表、一个开关和一套 TTL 上，两者既不同源也不同保留期，任一侧的开关或清理改动都会波及另一侧。

## Consequences

- 新增两个设置键与一条确认记录；运维入口挂在 usage 组内（`/admin/usage/request-audit-value-detail-settings`），因为本能力唯一的管理入口就是使用记录详情。
- 传输层尝试元数据（`httpattempt.Metadata`）新增三个可选字段与尝试级耗时／代理 ID；未打开标记时它们保持 nil／0。
- 只能覆盖已经产生使用记录、且走 Anthropic 上游的 `/v1/messages`。其它入口继续按「未采集」表达，不用空字段冒充已采集。
- 到期后 API 拒绝读取不等于删除；物理删除以在线主库的清理结果为准，积压只能靠计数与告警暴露。
- **读侧的复核规则与持久化边界逐条一致，不得更严**：模型名与 `metadata.user_id` 解析出的标识只在以**无歧义凭据前缀**开头时被拒（`bearer `／`basic `／`sk-`／`sk_`／`ghp_`／`gho_`／`xoxb-`／`xoxp-`／`-----begin`），头值只按闭集头名校验。`secret`／`apikey`／`password` 这类通用词**不做子串匹配**：它们会误拒后端确实留存的合法取值（含这些字样的不透明标识、beta 特性名、主机名标签），使界面显示得比实际留存更少，与已经披露的条目数自相矛盾。
- **读侧自己丢掉的条目必须显式告警**，且与载荷自带的 `truncated` 是两条独立事实：载荷的 `truncated` 说「采集时就没收下」，读侧的告警说「收到的载荷里有条目没通过本视图校验」。被读侧拒收的条目静默消失，会被管理员读成「客户端只发了这些」。凭据类头的排除是设计内行为，不计入该告警。
- 到期时刻不只约束 API：界面在窗口关闭的那一刻必须停止把 `stored` 显示成可读、停止提供揭示入口，并清除已经渲染在屏幕上的明文；揭示响应若在窗口关闭后才到达，同样按不可读丢弃。
